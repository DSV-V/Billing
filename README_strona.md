# Страница фактур склада ГДН: инструкция

Страница построена на React, Vite, TypeScript и `@supabase/supabase-js`. Работает только через Supabase: данные читаются из представлений `v_*` и `registers_for_month`, `register_variables_for_month`, `invoice_rate_info`, `nbp_currencies`, а меняются только через функции (`rpc`).

**Важно:** код написан, но не скомпилирован и не запущен. В среде разработки не было сетевого доступа, поэтому `npm install`, `tsc` и работа с живой базой не выполнялись. Первая сборка может выявить мелкие ошибки типов.

## Запуск

Нужен Node.js 18 или новее.

```bash
npm install
npm run dev        # режим разработки, http://localhost:5173
npm run build      # проверка типов и сборка в папку dist
npm run preview    # просмотр собранной версии
```

Переменные окружения необязательны: значения по умолчанию заданы в `src/lib/config.ts` и совпадают с контрактом (раздел 1). Если нужно переопределить их, скопируйте `.env.example` в `.env`.

| Переменная | Назначение |
|---|---|
| `VITE_SUPABASE_URL` | URL проекта Supabase |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | публичный ключ (publishable) |
| `VITE_RESET_REDIRECT_URL` | адрес страницы «Nowe hasło» для ссылки из письма сброса пароля |

Ключ `service_role` в проекте не используется, в переменные окружения и в код не добавляется.

## Адрес «Nowe hasło»

Ссылка из письма сброса пароля ведёт на `VITE_RESET_REDIRECT_URL`. Если переменная пуста, используется адрес, с которого открыта страница, с добавлением `/nowe-haslo`. Этот адрес нужно вписать в Supabase Auth: Site URL и Redirect URLs. Приложение распознаёт ссылку по событию `PASSWORD_RECOVERY`, поэтому работает при любом пути.

Для развёртывания на статическом хостинге нужен fallback на `index.html` для всех путей, иначе прямой переход на `/nowe-haslo` вернёт 404.

## Структура

- `src/lib/` — подключение, типы, форматирование, перевод ошибок, хук загрузки.
- `src/auth/` — вход, связка с `users`, роль, режим сброса пароля.
- `src/screens/` — экраны: вход, новый пароль, нет доступа, клиенты (1 и 1b), фактуры клиента (2), фактура с историей (3 и 5), позиция для фактуры и для szablonu (3b), реестры (4), szablon klienta (новый).
- `src/components/ui.tsx` — общие элементы: уведомления, загрузка, окно, значки.

Навигация внутри приложения сделана через состояние, без маршрутизатора. Адрес в браузере не меняется, кроме страницы сброса пароля.

## Известные риски

**1. Назначение администраторов в интерфейсе не реализовано.** Функция `set_client_assignments` заменяет весь список назначений целиком. Страница получает только администраторов и не знает идентификаторы пользователей с ролью `client`, поэтому сохранение могло бы снять клиентскую учётную запись, назначенную вручную. Поэтому кнопку «Zmień administratorów» убрали, а в коде нет ни одного вызова `set_client_assignments`. Назначения остаются за специалистом по базе. Если понадобится экран назначения, сначала нужно решение специалиста: как получать идентификаторы клиентских учётных записей, чтобы не потерять их при сохранении.

**2. Соответствие позиции и реестра по названию.** Признак «rejestr niewypełniony» в строке позиции сопоставляется по `register_name` с данными `registers_for_month` за тот же месяц. Если в одном клиенте два реестра с одинаковым названием, пометка может быть неверной. Нужно подтвердить, что названия уникальны в пределах клиента.

**3. Курс на уровне счёта, не на уровне позиции.** Пометка «Kurs nieaktualny» выводится по признаку `is_stale` счёта и по строкам `invoice_rate_info`. Поштучной пометки на каждый курс нет.

**4. Пустой итог категории.** Если в категории есть позиции, но строки в `v_invoice_category_totals` нет, страница выводит «Kurs niedostępny», а не ноль. Ноль выводится только для категории без позиций.

**5. Тексты вне глоссария.** Все тексты ошибок сверены с разделом 6 описания, расхождений нет, кроме `CURRENCY_NOT_SUPPORTED` (текст согласован отдельно). Тексты кнопок и подписей сверены с разделом 9. Остальные тексты, которых нет в описании, написаны страницей: «Nieprawidłowy email lub hasło.», «Hasło musi mieć co najmniej 8 znaków.», «Hasła nie są takie same.», «Brak klientów» (есть в описании), «Brak faktur», «Brak zdarzeń», «Brak rejestrów», «Brak zmiennych», «Brak pozycji» (есть в описании), «Wybierz walutę faktury», «Wybierz administratora», «Podaj cenę nie mniejszą niż 0», «Podaj ilość nie mniejszą niż 0», «Wybierz rejestr i zmienną», «Usunąć pozycję?», «Zamknij fakturę», «Otwórz ponownie», «Kurs niedostępny» (есть в описании), «Brak kursu». Все тексты нужно проверить носителем польского языка.

**6. Пустой набор неоднозначен.** `invoice_rate_info` возвращает пустой набор и при отсутствии доступа к счёту, и тогда, когда курс не нужен. Страница на этом не ломается, потому что счёт приходит из `v_invoices`, где RLS уже скрывает чужие счета.

**7. Курс 4 знака.** Курсы выводятся с четырьмя знаками после запятой, как решено. База хранит шесть. Суммы страница не пересчитывает.

## Изменения последней итерации

- **Три режима ilości** при добавлении: z rejestru, ręcznie, procent. Режим выбирается только при добавлении; при редактировании переключатель не показывается.
- **Пустая ilość ręczna** отправляется как NULL. База считает её как 0, в фактуре и в szablonie. Предупреждения нет.
- **Checkbox «Dodaj do szablonu»** при добавлении позиции в фактуру передаёт `p_add_to_template`. Одна транзакция в базе, откат на стороне страницы не нужен.
- **Ekran szablonu** (кнопка «Szablon» на экране фактур клиента): список, dodawanie, zmiana, usuwanie. Klient tylko czyta. Kolejności nie zmieniamy, bo porządek nie ma znaczenia. Na ekranie szablonu pokazujemy tylko liczbę, nazwy reestrów i zmiennych nie są potrzebne.
- **Pozycja procentowa** w tabeli faktury pokazuje procent i kwotę z bazy, bez ceny i waluty.

**Nieprzetestowane:** dodawanie pozycji procentowej do faktury. Specjalista potwierdził tryb procentowy w szablonie i przy otwieraniu miesiąca, ale nie potwierdził `add_position` z `quantity_mode = 'percent'`. Jeśli zapis się nie uda, przyczyna jest po stronie bazy.

**Nie zrobione:** zmiana kolejności szablonu (decyzja: nie jest potrzebna), blokada zmiany trybu w bazie (decyzja: na tym etapie nie jest potrzebna).
